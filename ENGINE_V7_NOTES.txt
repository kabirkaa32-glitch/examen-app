محرك الحراسة — تحديث v7

التغييرات:
1) تفعيل محرك Python الفعلي كخيار التوليد الأساسي بدلاً من تشغيل محرك JavaScript وحده.
2) الإبقاء على محرك JavaScript كبديل تلقائي إذا تعذر الاتصال بمحرك Python.
3) زيادة دورات إعادة بدء البحث داخل المهلة نفسها؛ الإصدار السابق كان يقسم المهلة إلى أربع دورات فقط تقريباً مهما ارتفع عدد المحاولات.
4) حفظ أفضل توزيع معروف وإرساله كبداية دافئة للدفعة التالية، مع مقارنة النتائج بمفتاح تقييم مرتب حسب أولوية القيود.
5) عرض المحرك الفعلي، وعدد الدورات/التكرارات، والتنبيه عند انتهاء مهلة الدفعة مع الاحتفاظ بأفضل نتيجة.
6) تحويل معرّف الأستاذ الراجع من Python إلى نوع المعرّف الأصلي في قاعدة البيانات؛ يمنع تعثر الحفظ عندما يكون المعرّف رقماً في قاعدة البيانات ونصاً داخل Python.
7) الإبقاء على نافذة التوقف/المواصلة، والمعاينة، وقبول وحفظ أفضل حل، وعدم اعتبار انتهاء مهلة دفعة واحدة سبباً لإنهاء البحث كله.

القيود:
- الإعفاءات والتعارض الزمني وحدّ التكليفات اليومية وقواعد أستاذ المادة وحدّ الاحتياط قيود صارمة في المحرك.
- توازن الحصص/الأيام/الساعات والحصص المنفردة تُقيّم حسب قواعد البرنامج وخيارات السماح بالاستثناء.
- إذا كانت القيود متناقضة أو لم يوجد حل كامل، يعرض المحرك أفضل حل وجده والتشخيص والحصص غير الموزعة؛ لا يمكن ضمان حل كامل عندما تكون المسألة مستحيلة رياضياً.

الاختبار:
- تم فحص صياغة Python واختبار توزيع صغير يتضمن حراسة واحتياطاً وقواعد أستاذ المادة.

تحديث v7.1 — شرطا التوازن الأساسيان:
- أصبح فارق عدد الحصص وفارق أيام الحراسة (حد أقصى 1 لكل منهما) أعلى أولوية من القيود التفضيلية داخل مفتاح تقييم المحرك.
- يمنع زر «اعتماد وحفظ» حفظ أي نتيجة يكون فيها فارق الحصص أو الأيام أكبر من 1؛ تظهر رسالة توضح الفارق وتطلب مواصلة البحث أو مراجعة القيود.
- لا يعني هذا أن كل مجموعة بيانات لها حل ممكن؛ إذا تعارض الشرطان مع الإعفاءات أو توقيت الاختبارات أو الحد اليومي، ستبقى النتيجة للمعاينة فقط ولن تُحفظ باعتبارها حلاً معتمداً.
